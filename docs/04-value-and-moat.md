# 这个项目值不值得做，护城河在哪

结论先说：**工具本身不值钱，把「谁在跑什么、还活着吗」变成可信任的一层，值钱。**

---

## 1. 分三层看价值

| 层 | 用户愿意付出的东西 | 天花板 |
|---|---|---|
| **L1 看板** | 免费，装了就忘 | 又一个 nvitop 皮肤，star 不过千 |
| **L2 值班员** | 免费但会被推荐，会留在托盘 | 3–5k star，成为这个场景的默认答案 |
| **L3 调度层**（v0.5+ 租约 / 排队 / 空占用回收） | 团队愿意付钱或部署 | 真正的商业面，也是最难的面 |

L1 已经有 4770 个仓库在抢，做进来就是分母。**我们的全部赌注是 L2 能不能被信任，因为 L3 建在 L2 上。**

## 2. 谁真的需要

- **单机多卡的个人/小团队**：训练 + 生图 + 推理混跑，靠 `nvidia-smi` 和任务管理器人工盯。中文 ComfyUI 生态的用户量是十万级。
- **共享工作站**：实验室/工作室几个人共用一个 GPU 盒子，谁占着卡、谁的进程挂了，靠群里问。
- **远程机器**：eGPU 盒子、家里机器挂机跑训练，人不在旁边，**出事了没人知道**——这是最痛的一档，也是播报的核心场景。

他们不缺数字，缺的是三句话：`这是哪个任务`、`它还正常吗`、`出事了叫我`。

## 3. 竞品为什么不会被顺手补上

| 竞品类型 | 它为什么做不了这件事 |
|---|---|
| nvitop / nvtop / gpustat | 世界观是「进程与指标」，数据模型里没有任务，改成任务语义等于重写；nvtop 只跑 Linux，在 Windows 上根本不在场 |
| DCGM / dcgm-exporter | 指标极全但没有任务概念，官方支持列表只有 Linux；Windows 不可用 |
| W&B / SwanLab / TensorBoard | 要改训练代码上报，覆盖不到 ComfyUI、下载、推理服务；跨任务不统一 |
| ComfyUI 插件（ComfyQueueBar 等） | 只懂 ComfyUI，出了那个页面就瞎 |
| 桌面传感器工具（gpu-hot 等） | 只有温度风扇，没有进程语义 |
| Windows 任务管理器 | 只有 `python.exe` 和总占用，**这正是痛点本身** |

**结构性空白**：Windows 原生 × 多卡 × 任务语义 × 主动播报，四者交集为空。不是没人想到，是每一类玩家都被自己的世界观锁住了。

## 4. 护城河怎么设计（四层，逐层加厚）

**第一层：归属准确性（工程护城河）**
只有自己 spawn 的进程能保证语义正确。所以 `gpulease run` 包装器不是可选功能，是**地基**：注入 `GPULEASE_RUN_ID`、拿退出码、收 stdout、记录 pid 树。别人做监控只能读，我们能写——这是方向性差异。
对外部进程诚实标注 `external`，不猜。**猜错一次，播报就永久失去信任。**

**第二层：规则与话术库（数据护城河）**
规则的阈值、以及"这句话怎么说"，来自真实故障样本的积累：OOM、NaN、卡死、掉卡、僵尸进程、磁盘满、下载停滞。这类语料没有开源数据集，只能自己攒。攒到 50 条真实故障模式时，别人抄界面容易，抄判断难。

**第三层：生态位（分发护城河）**
两条免费入口：① DSH 插件（一行安装的适配层，复用同一套 HTTP 接口）；② ComfyUI 生态（生图人群的默认工作台）。
工具类项目 star 再多也难变现，但**入口位置会复利**——v0.5 的租约与排队从同一个托盘长出来。

**第四层：网络效应（弱，别指望）**
单机工具天然没有网络效应。唯一的社会性来自"共享机器的团队"：多人看同一个面板才有协作价值。这一层只影响 L3，v1 只是把单机体验做到无可替代。

## 5. 三个必须现在锁死的设计决策

1. **`run` 包装优先于只读看板**。只读派拿不到退出码和 stdout，"失败"判定会瘸一条腿；先做 `run`，纳入外部进程作为补充。
2. **播报质量 > 数据丰富度**。少一条曲线没人退订，一次误报就卸载。宁可漏报。
3. **单 exe 零依赖**。目标用户不会为一个看板装 Node、Python、Docker；双击能跑是入场券。

## 6. 诚实的风险

| 风险 | 概率 | 应对 |
|---|---|---|
| NVIDIA 或系统厂商把任务语义做进驱动面板 | 中 | 他们做不了跨框架的语义层；且 Windows 侧没有动机 |
| 任务管理器未来显示命令行 | 低 | 显示命令行也仍然不知道进度与健康 |
| W&B/SwanLab 下沉到本地轻量观测 | 中 | 它们要改代码；我们零侵入 + 覆盖非训练任务 |
| 大厂把类似功能塞进 ComfyUI 生态 | 中 | 我们做跨工具的统一层，插件只做自家 |
| 自己变成又一个看板 | **高** | 用「第一眼能看出这是我的训练在跑」当唯一验收标准 |

**天花板估计**：star 3–5k，长期成为该场景的默认推荐；商业价值不在 v1，在 v0.5+ 的租约与排队。

## 7. 怎么判断做成了

不看 star，看三个数：

- 装了的人第二天还开着（D7 留存）
- 告警点开后的"确实如此"比例（命中率 > 80%）
- 有人把它写进自己的启动脚本/教程（自发传播）

第一个达标，才允许做自动调度。
